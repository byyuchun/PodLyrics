# 离线词典判难度，LLM 只做可选的语境释义

字幕中要标注"用户可能不认识的词"，而"难"因人而异。我们没有让 LLM 按用户水平筛词，而是内置一份裁剪自 ECDICT 的离线词典（词频、考试标签、变形表、通用中文释义），由它决定每个词的档位，用户的水平（Proficiency）只是一个本地过滤条件；用户自备的 OpenAI 兼容模型仅在开启时为已被标注的词补一条结合上下文的短释义（Gloss）。

原因：档位过滤必须即时、免费、可反复调，让模型判难度会使每次调整都变成一次付费请求，且结果不稳定；离线词典还保留了原项目"零配置、完全离线"的承诺，Gloss 只是增强层，关掉后一切照常。代价是 ECDICT 的标签覆盖不完整（无标签词按词频兜底），以及释义是通用义项而非语境义，后者正是 Gloss 存在的理由。

## 考虑过的替代

- **纯 LLM**：每集全文发给模型标注。语境最准，但拖动难度滑块要重新请求，成本与延迟不可控，且无法离线。
- **纯词典**：完全放弃 LLM。零成本，但 pitch、chunk 这类多义词在播客语境下的释义经常不对。
